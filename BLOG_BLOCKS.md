# Документация по системе контентных блоков

## Список всех блоков

1. **Checklist** - Чеклист с пошаговыми инструкциями для выполнения задач
2. **CtaAfterRead** - Призыв к действию после прочтения статьи
3. **CtaCalc** - Призыв к действию с калькулятором расчета стоимости
4. **ExpertQA** - Вопрос-ответ с экспертом по теме
5. **ExpertTip** - Совет эксперта по теме статьи
6. **FAQ** - Часто задаваемые вопросы с ответами
7. **FinalVerdict** - Итоговый вердикт или заключение статьи
8. **ProsCons** - Таблица плюсов и минусов сравниваемых решений
9. **RankingList** - Рейтинговая таблица по критериям
10. **ScoreRating** - Оценка по балльной системе

## Примеры использования (MDX)

### Checklist
```mdx
<Checklist title="Чеклист подготовки к ремонту">
- [ ] Заключить договор
- [ ] Получить доступ к объекту
- [ ] Подготовить строительные материалы
</Checklist>
```

Пример использования через шорткод/шаблон:

```
[!TEMPLATE key="checklist" title="Чек-лист подготовки"]
- Заключить договор
- Получить доступ к объекту
- Подготовить строительные материалы
[/!TEMPLATE]
```

Короткий алиас:

```
[!CHECKLIST title="Чек-лист подготовки"]
- Заключить договор
- Получить доступ к объекту
- Подготовить строительные материалы
[/!CHECKLIST]
```

### CtaAfterRead
```mdx
<CtaAfterRead 
  title="Готовы начать ремонт?"
  description="Получите бесплатную консультацию специалиста"
  ctaText="Заказать звонок"
/>
```

### CtaCalc
```mdx
<CtaCalc 
  title="Рассчитайте стоимость ремонта"
  description="Онлайн-калькулятор поможет определить бюджет"
/>
```

### ExpertQA
```mdx
<ExpertQA 
  question="Как выбрать плитку для ванной?"
  answer="Эксперт рекомендует обращать внимание на водопоглощение и класс износостойкости."
  expert="Иван Петров, главный дизайнер"
/>
```

### ExpertTip
```mdx
<ExpertTip 
  title="Совет эксперта"
 content="Для маленькой ванной комнаты лучше использовать светлую плитку визуально увеличивает пространство."
/>
```

### FAQ
```mdx
<FAQ items={[
  { question: "Сколько времени занимает ремонт?", answer: "Обычно от 2 до 4 недель в зависимости от сложности." },
  { question: "Можно ли сделать ремонт под ключ?", answer: "Да, мы предлагаем комплексное решение под ключ." }

```

### FinalVerdict
```mdx
<FinalVerdict 
  title="Итог"
  content="Для бюджетного варианта рекомендуем вариант А, для качества - вариант Б."
/>
```

### ProsCons
```mdx
<ProsCons 
  title="Сравнение материалов"
  pros={[ "Долговечность", "Влагостойкость", "Эстетичный вид" ]}
  cons={[ "Высокая цена", "Сложность монтажа", "Необходимость специалистов" ]}

```

### RankingList
```mdx
<RankingList 
  title="Рейтинг производителей плитки"
  items={[
    { rank: 1, name: "Kerama Marazzi", description: "Лучшее соотношение цена/качество" },
    { rank: 2, name: "Porcelanosa", description: "Премиум-сегмент" },
    { rank: 3, name: "Atlas Concorde", description: "Надежный выбор" }
  ]}

```

### ScoreRating
```mdx
<ScoreRating 
  title="Оценка качества материалов"
  score={8.5}
  maxScore={10}
  description="По результатам экспертной оценки"
/>
```

## Правила вставки блоков в статьи

1. Блоки можно использовать в любом порядке в пределах статьи
2. Один и тот же тип блока может встречаться несколько раз в одной статье
3. Блоки должны быть семантически связаны содержимым статьи
4. Нельзя вкладывать блоки друг в друга
5. Каждый блок должен иметь уникальный заголовок, если используется несколько одинаковых блоков
6. Блоки вставляются непосредственно в текст статьи в формате MDX
7. Не рекомендуется использовать более 3-4 блоков одного типа в одной статье
8. Обязательно проверять валидность props перед публикацией

## Best Practices

- **Checklist** - используйте для инструкций, руководств, пошаговых процессов
- **CtaAfterRead** - размещайте в конце статьи для переконверсии читателя
- **CtaCalc** - вставляйте после разделов с расчетами или ценами
- **ExpertQA** - применяйте для разъяснения сложных вопросов
- **ExpertTip** - добавляйте в места с советами и рекомендациями
- **FAQ** - используйте после основного контента для часто задаваемых вопросов
- **FinalVerdict** - ставьте в самом конце статьи как заключение
- **ProsCons** - вставляйте при сравнении решений или продуктов
- **RankingList** - используйте для рейтингов и сравнительных таблиц
- **ScoreRating** - применяйте для оценок и аналитики

## Props для компонентов

### Checklist
- `title` (string) - заголовок чеклиста
- `children` (ReactNode) - элементы списка (checkboxes)

### CtaAfterRead
- `title` (string) - заголовок CTA
- `description` (string) - описание
- `ctaText` (string) - текст кнопки
- `analyticsId` (string, optional) - ID для аналитики

### CtaCalc
- `title` (string) - заголовок
- `description` (string) - описание
- `analyticsId` (string, optional) - ID для аналитики

### ExpertQA
- `question` (string) - вопрос
- `answer` (string) - ответ
- `expert` (string) - имя эксперта

### ExpertTip
- `title` (string) - заголовок совета
- `content` (string) - содержание совета

### FAQ
- `items` (Array<{question: string, answer: string}>) - массив вопросов и ответов
- `addSchemaMarkup` (boolean, default: true) - добавлять JSON-LD разметку

### FinalVerdict
- `title` (string) - заголовок вердикта
- `content` (string) - содержание вердикта

### ProsCons
- `title` (string) - заголовок таблицы
- `pros` (string[]) - список преимуществ
- `cons` (string[]) - список недостатков

### RankingList
- `title` (string) - заголовок рейтинга
- `items` (Array<{rank: number, name: string, description: string}>) - элементы рейтинга

### ScoreRating
- `title` (string) - заголовок оценки
- `score` (number) - текущий балл
- `maxScore` (number, default: 10) - максимальный балл
- `description` (string, optional) - дополнительное описание

## Особенности использования

- **FAQ** - автоматически генерирует JSON-LD разметку для улучшения SEO (можно отключить через `addSchemaMarkup: false`)
- **CtaAfterRead и CtaCalc** - имеют встроенную аналитику для отслеживания эффективности
- **ExpertQA** - поддерживает форматирование HTML в поле `answer`
- **Checklist** - сохраняет состояние чекбоксов между сессиями пользователя
- **RankingList** - может отображаться в виде карточек или таблицы в зависимости от ширины экрана
- **ProsCons** - автоматически чередует цвета строк для лучшей читаемости
- Все CTA-компоненты могут быть настроены на отправку событий в Google Analytics

## Информация об аналитике для CTA-компонентов

CTA-компоненты (CtaAfterRead, CtaCalc) поддерживают сбор аналитических данных:

1. **Отслеживание кликов** - автоматически регистрирует события при клике на кнопку
2. **Параметры аналитики**:
   - `eventCategory`: 'CTA Click'
   - `eventAction`: название компонента (например, 'CtaAfterRead')
   - `eventLabel`: заголовок компонента или analyticsId
3. **Настройка через props**:
   - `analyticsId` - позволяет задать уникальный идентификатор для отслеживания
4. **События отправляются в GA4** при клике на кнопку призыва к действию
5. **Аналитика работает только при наличии настроенной GA4** на сайте
6. Для тестирования аналитики используйте режим разработки Google Tag Assistant
